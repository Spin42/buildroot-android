# Lenovo Tab3 7 Essential (TB3-710F)

MediaTek MT8127 (4x Cortex-A7, 1 GiB RAM, Mali-450), MT6323 PMIC, 8 GB eMMC, 1024x600 LVDS panel.
Mainline has almost no support for this SoC yet (`mt8127.dtsi` has CPUs, timers, interrupt controller and UARTs only), so
the kernel fork adds the PLL, CPU mux and I2C clock gates, the pin controller, the PMIC wrapper and the I2C buses, and everything
else still runs on the state the stock bootloader leaves behind (fixed clocks).

## Boot chain

preloader -> LK (stock, unlocked) -> `boot` partition (kernel with appended DTB + initramfs) -> `/init` mounts the
persistent root on `userdata` and `switch_root`s into it. If that fails (no eMMC, no ext4, no `/sbin/init`, or `/.rescue`
exists on the root) the initramfs itself keeps running as a rescue system, with ssh over USB.

* LK has **no** `fastboot boot`, every test image is flashed to the `boot` partition (16 MiB max).
* LK loads the kernel at `0x80008000`, the ramdisk at `0x84000000` and passes ATAGs only: the DTB is appended to the zImage
  and the kernel command line is built in (`CONFIG_CMDLINE_FORCE`).
* `boot.img` is built by `board/tb3_710f/scripts/create_boot_image.sh` (Android boot image v0, `mkbootimg.py`).
* **Always** use `fastboot -s <serial>` (see `scripts/flash.sh`): other devices are often attached to the same host.

## Reboot to the bootloader from Linux

LK reads the MT6323 RTC power-down register PDN1 (PMIC register `0x802c`): bit 13 requests fastboot, bit 4 recovery.
`reboot-mode bootloader|recovery|normal` (package `tb3-tools`) writes it through the SoC's PMIC wrapper (`/dev/mem`, the wrapper is
initialised by the preloader) and reboots through the watchdog. The ssh session hangs when it fires: call it fire and forget.
`tb3-pmic read|write <reg>` gives raw access to the PMIC.

## What works

| Feature | State |
|---|---|
| 4 CPUs | works (`mediatek,mt81xx-tz-smp`) |
| CPU frequency scaling | works (`mediatek-cpufreq`, 598 / 747.5 / 1040 / 1196 / 1300 MHz, VPROC 1.15 to 1.30 V); no thermal driver yet |
| PMIC | MT6323 through the PMIC wrapper: regulators (VPROC, VGP2), interrupt on `PWRAP_INT` (EINT24), RTC (keeps the time across reboots), power key, power-off |
| Pin controller, GPIO | works (`mediatek,mt8127-pinctrl`, 143 GPIOs, EINT); `gpioinfo`/`gpioget`/`gpioset` (libgpiod 1.6, `GPIO_CDEV_V1`) |
| I2C | works, 100 kHz default (the I2C blocks run from the 273 MHz bus clock, `MAINPLL / 4`): I2C2 shows the BMA222 accelerometer (0x18) and the bq24296 charger (0x6b); I2C1 carries the touch controller (0x40) |
| RAM | 1 GiB (highmem) |
| Display | bootloader framebuffer as `simple-framebuffer` (RGB565, 1024x600), fbcon |
| USB | gadget mode (`g_ether`), host mode untested; MT8127 USB2 PHY driver in `patches/linux` |
| eMMC | works, 52 MHz SDR (DDR multi-block writes fail), partitions mount |
| Watchdog | works, kicked by userspace |
| Touch | works: Silead GSL3670 on I2C1 (0x40), VGP2 2.8 V supply, reset GPIO45, interrupt EINT7, multi-touch (up to 5 fingers); the coordinates cover the sensor area, so a calibration matrix in userspace is needed to reach the glass edge exactly |
| Accelerometer | works: Bosch BMA255 family (chip id 0xFA) on I2C2 0x18 through `bmc150-accel` (IIO, 12 bit, polled; the stock board has no interrupt wiring); the DT carries the stock mount matrix. It is the only sensor of the tablet: the stock configuration has no light, proximity, gyroscope or magnetometer |
| Charger, battery, audio, WiFi/BT/GPS (CONSYS), cameras, thermal | not started (the charger answers on I2C2 0x6b); WiFi is being ported as out-of-tree modules, see the packages below |

## Partitions

The eMMC keeps the stock MediaTek layout:

| Device | Content | Used here |
|---|---|---|
| `mmcblk0boot0/1` | preloader | untouched |
| `mmcblk0p2`, `p3` | `protect_f`, `protect_s` | untouched (blank) |
| `mmcblk0p4` | `sec_ro` | untouched (raw) |
| `boot` (raw offset `0x1d80000`) | kernel + initramfs | `boot.img` |
| `recovery` (raw offset `0x2d80000`) | recovery | untouched (TWRP recommended) |
| `mmcblk0p5` | Android `system` (ext4) | untouched |
| `mmcblk0p6` | Android `cache` (ext4) | untouched |
| `mmcblk0p7` | Android `userdata` | persistent root (ext4) |

The last 21 MiB of `userdata` are the vendor "BMT pool"; the filesystem is kept at the stock size (`5309440K`).

## Writing the root filesystem

**This replaces the Android userdata.** Back it up first if you care about it
(`ssh root@10.0.42.1 'dd if=/dev/mmcblk0p7 bs=1M' | zstd -T0 -o userdata.img.zst`). From the RAM rescue system:

    scp output/images/rootfs.ext4 root@10.0.42.1:/tmp/
    ssh root@10.0.42.1
    dd if=/tmp/rootfs.ext4 of=/dev/mmcblk0p7 bs=1M conv=fsync
    sha256sum /tmp/rootfs.ext4 && dd if=/dev/mmcblk0p7 bs=1M count=256 | sha256sum   # must match
    e2fsck -f /dev/mmcblk0p7 && resize2fs /dev/mmcblk0p7 5309440K

Then reboot: the initramfs finds the ext4 root and switches to it. Changes to the files afterwards are made over ssh, only a
full image replace needs this again. Create `/.rescue` on the persistent root to force the rescue system.

## Kernel

The kernel comes from the [linux-mt8127](https://github.com/mlainez/linux-mt8127) fork (stable 6.18 LTS plus topic
branches, see its `AGENTS.md` for the branching and promotion rules). The defconfig builds `6.18/staging`; use `6.18/rc` or
`6.18/release` once they are promoted, and pin `BR2_LINUX_KERNEL_CUSTOM_REPO_VERSION` to a commit SHA for test builds.
The kernel configuration lives here, in `board/tb3_710f/linux.config`.

To build against a local checkout of the fork (it has to be on the branch you want), create `output/local.mk`:

    LINUX_OVERRIDE_SRCDIR = /path/to/linux-mt8127

and run `make BR2_PACKAGE_OVERRIDE_FILE=$PWD/output/local.mk ...`.

## Touch firmware

The GSL3670 needs a firmware that Silead does not allow redistributing, so it is not in git. It is extracted from the stock kernel source
(`drivers/input/touchscreen/mediatek/GSL3670/gsl_ts_fw.h`) into the rootfs overlay (ignored by git):

```
board/tb3_710f/scripts/extract_silead_fw.py <gsl_ts_fw.h> GSLX68X_FW_2 \
    board/tb3_710f/overlay/lib/firmware/silead/gsl3670-tb3-710f.fw
```

`GSLX68X_FW_2` is the image that matches this panel; `GSLX68X_FW_1` loads fine but reports scrambled coordinates.

## Packages of this board

| Package | Role |
|---|---|
| `tb3-tools` | PMIC access and `reboot-mode` |
| `tb3-firmware` | Proprietary firmware (Silead touch, CONSYS WiFi); collect it with `scripts/prepare_firmware.sh` |
| `mt8127-btif`, `mt8127-consys`, `mt8127-wmt`, `mt8127-wlan` | The CONSYS WiFi stack as out-of-tree kernel modules, one package per layer (link, platform, protocol core, WiFi driver) built from the `mt8127-consys` repository |
